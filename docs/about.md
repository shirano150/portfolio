# 소개

## 한 줄 소개

> 단순히 기능을 구현하는 개발자가 아니라, 서비스의 안정적인 운영과 지속 가능한 구조를 우선으로 고민하는 게임 서버 개발자입니다.

## 자기소개

2009년부터 PC MMO·MORPG, 세션·매치형 게임, 모바일 RPG까지 장르가 다른 온라인 게임의 서버를 개발해 왔습니다. 장르마다 접속 방식과 트래픽 패턴이 달라서 채널형 서버, 로비와 실시간 인게임 서버 분리, 상태 없는 API 서버와 캐시·DB 샤딩처럼 서비스 특성에 맞는 구조를 설계하고 운영했습니다.

최근 세 개 타이틀에서는 팀장·파트장으로 프로토타입부터 서비스 오픈까지 서버 개발을 이끌었습니다. AWS 인프라를 직접 구성하고 CloudFormation IaC, Jenkins·Ansible 배포 자동화, Prometheus·Grafana·Sentry 모니터링, Fluentd·S3 로그 파이프라인을 오픈 전에 갖춰 라이브 이후의 운영까지 고려했습니다. 그 전에는 서버 팀장으로 PC MORPG의 한국·중국 서비스 오픈을 맡았고, 일본 모바일, 글로벌 모바일, Steam 얼리 액세스까지 여러 지역과 플랫폼의 오픈을 경험했습니다.

개발팀 밖에서도 서비스를 이해하고 다룰 수 있게 하는 일을 중요하게 여깁니다. 운영팀·QA팀이 직접 쓰는 모니터링·로그 분석·백오피스 도구를 만들었고, Wiki를 구축해 유관 부서와의 협업 체계를 정리했습니다.

최근에는 Flutter로 앱을 직접 기획·개발·출시하고 있고, Claude Code 같은 AI 개발 도구를 실무에 도입해 생산성을 높이고 있습니다.

## 일하는 방식

!!! info "🏗️ 운영을 고려한 설계"
    개발 초기부터 장애 대응, 모니터링, 배포 자동화를 함께 설계해 라이브 이후에도 안정적으로 운영되는 구조를 만듭니다.

!!! success "🔧 기술에 종속되지 않는 선택"
    C++, Java, Python, Go, C# 등 여러 언어와 스택을 실무에 적용하며 각 기술의 장단점을 이해하고, 서비스 요구사항에 맞는 기술을 선택합니다.

!!! warning "📝 유관부서 협업과 문서화"
    Wiki를 구축해 유관 부서와의 협업 체계를 정립하고, 운영팀·QA팀이 직접 쓸 수 있는 모니터링·로그 분석·백오피스 도구를 만들어 기술 정보를 팀 밖으로 공유해 왔습니다.

!!! example "🤝 팀 전체의 품질"
    우선순위 조정과 일정 관리, 코드 및 구조 리뷰로 잠재적 리스크를 미리 관리하고, 장애가 나면 원인 분석과 구조 개선으로 같은 문제가 반복되지 않게 합니다.

!!! tip "📈 서비스 특성에 맞는 구조"
    서비스마다 다른 트래픽 패턴과 실시간 처리 요구사항을 고려해 구조를 설계하고, 새 프로젝트에서도 요구사항을 빠르게 이해해 적응합니다.
